   Found 1 legacy image ("Sunday Service Title", images/test_image.jpg).

   run 2: **0 generated, 1 skipped** (no-op). Variants now exist on disk
   (thumb 320×240, soft, strong); main file untouched.
3. **Duplicate of a re-fit image:** confirmed via test — re-uploading the
   bytes of an image set to fit "cover" returns duplicate=True pointing at
   the SAME image id with fit still "cover"; DB still has 1 row, fit kept.
4. **Phone-test bugfix — version 4 (root cause found, definitive):** the same
   mislabel recurred, and then a NEW symptom appeared ("list didn't refresh
   until I left and came back"). Root cause is scope, not the guards: the
   upload batch (`handleImageBatch`) lives at the IIFE top level, but the list
   refresh `doSearch` was a function NESTED inside `renderImages` — so the
   batch's `doSearch()` tail call was a ReferenceError on EVERY batch
   completion. In the original code that throw hopped into the upload's
   `.catch` → mislabeled a successful upload "failed — request error" AND
   bumped the counter twice ("2 of 1"). The v3 try/catch swallowed the
   ReferenceError (correct "done"/"1 of 1") but silently killed the in-place
   list refresh — hence "no update until I revisited" the tab. Fix: a top-level
   `currentImagesRefresh` slot that `renderImages` assigns its live `doSearch`
   into, and the batch tail calls that instead. `node --check` clean; suite
   still 115 green. `control.js` include bumped to `?v=4`.

   eslint runs fully offline.
6. **Automatic cache-busting:** replaced the hand-bumped `?v=N` with a
   `{% staticver %}` template tag (`presentation/templatetags/versioned_static.py`).
   It appends `?v=<source-file-mtime>`: dev resolves the real file via the
   staticfiles finder (every edit re-versions), and in the portable build the
   onedir copy inside `_internal` keeps its BUILD-TIME mtime, so the version is
   stable per build and changes exactly when the app is rebuilt. If the file
   cannot be resolved it falls back to the plain URL (page never breaks). Every
   JS/CSS reference in index.html, control.html and display.html now uses it.
   Proclaim.spec gained `presentation.templatetags` + `.versioned_static` as
   hiddenimports because `{% load %}` imports them lazily at render time and
   PyInstaller cannot statically see them.
7. **Duplicate after re-fit (contain):** new test
