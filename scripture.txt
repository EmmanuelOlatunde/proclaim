This document explains the **scripture** side of the ChurchCast app end to
end so a fresh AI can understand it and troubleshoot. It was written against
the real code in `/home/mohbohlahji/Projects/proclaim`.

Good entry points if you are debugging:
- Parser + slide builder: `presentation/scripture.py`
- HTTP endpoint: `presentation/views.py` → `scripture_parse` (line ~223), `scripture_books` (~234)
- WebSocket command path: `presentation/consumer.py` → `_present_scripture` (~191)
- Control page (phone) scripture tab: `presentation/static/presentation/js/control.js` → `renderScripture`, `previewScripture`
- Display rendering: `presentation/static/presentation/js/display.js` → `renderScripture`

## 1. One-sentence summary

The user types a Bible reference like `John 3:16` on the phone; the server
parses it against a bundled, offline King James Version, builds display
"slides", and a full snapshot goes over WebSocket to the laptop display page.

## 2. The Bible data — `presentation/data/kjv.json`

- One JSON file, loaded **once** into a module-level cache `_BIBLE_CACHE`
  (`scripture.py:_load_bible`, line 84). If the file is missing, it returns
  `{}` — which silently makes **every** reference "not found" (404). This is
  a classic "everything scripture broke" root cause: check the file exists.
- Size: ~4.8 MB, **66 books, 31,102 verses** (verified).
- Structure (verified on disk):
  ```json
  {
    "Genesis": { "1": [ {"v": 1, "text": "..."}, ... ], ... },
    "Psalms": { "23": [ {"v": 1, "text": "The LORD is my shepherd; I shall not want."}, ... ] },
    "1 Samuel": {...}, "Song of Solomon": {...}, ...
  }
  ```
  - **Top level is the CANONICAL book name** used for display too
    (`Psalms`, `1 Samuel`, `1 John`, `Song of Solomon`).
  - Keys are chapter numbers as **strings**.
  - Each chapter is a **list** of `{"v": int, "text": str}` (verse number +
    KJV text).
- Provenance: generated by `/tmp/opencode/build_kjv.py` from
  `https://github.com/thiagobodruk/bible/blob/master/json/en_kjv.json`
  (a public-domain KJV dump). The source metadata used Portuguese book names,
  so the convert script renamed to a canonical 66-name list — that is why the
  canonical names, not the source's, are the JSON keys.

## 3. Parsing a reference — `scripture.py:parse_reference` (line 146)

Returns `None` (→ caller returns HTTP 400) if the reference does not parse.

Steps:

1. `strip()` the input.
2. `_match_book(ref_str)` (line 116) — find the **longest** book alias at the
   start of the string. The alias table `_BOOK_ALIASES` (line 14) maps
   abbreviations/full names to canonical names:
   - `"gen"`→Genesis, `"ps"`/`"psalm"`/`"psalms"`→`Psalms`,
     `"jn"`→John, `"1john"`→`1 John`, `"song"`/`"songofsolomon"`→`Song of Solomon`, …
   - Matching uses `_consume` (line 102): case-insensitive and
     **whitespace-tolerant** (spaces anywhere inside the alias are allowed) —
     so `1 John 1:9` and `1John 1:9` both work.
   - **Boundary rule:** after the matched alias, the next non-space character
     MUST be a digit (the chapter number). This is why `"psalm"` matches
     `Psalm 23` but `"song"` alone will NOT match `Song 2:1` — the longer
     alias `"songofsolomon"` wins for `Song of Solomon 2:1`, and a bare
     `Song 1:1` actually resolves to **Song of Solomon 1:1** via the shorter
     `"song"` alias (verified).
3. Regex the remainder: `^(\d+)(?::(\d+)(?:-(\d+))?)?$` (line 157):
   - `chapter` only → whole chapter (e.g. `Psalm 23`)
   - `chapter:verse` → single verse (`John 3:16`)
   - `chapter:verse-verse` → range (`Genesis 1:1-5`, `Romans 8:28-30`)
   - Commas (`Genesis 1,1`), out-of-order ranges, or a range bigger than the
     chapter are NOT handled → they fail the regex → 400.
4. Returns a dict: `{book, chapter, verse_start, verse_end, display}`.
   `display` is the canonical label used everywhere (`"Psalms 23"`,
   `"John 3:16"`, `"Genesis 1:1-5"`).

Gotchas / expected results (all verified against the running code):
- `"j"`, `"jo"`, `"john"` (no chapter) → `None` → **HTTP 400**. The control
  page queries this endpoint on every keystroke, so typing shows a stream of
  400s in the server log — **that is normal, not a bug**.
- `"Pslams 23"` (typo) → 400.
- `"John 3:99"` parses fine (99 <= regex) but yields **0 slides** → the
  endpoint returns **404 "passage not found in local Bible"** (see §5).
- Leading/trailing whitespace is fine; mixed case is fine; `JOHN 3:16` works.

## 4. Building slides — `scripture.py:build_slides` (line 182)

1. Looks up `bible[book][str(chapter)]`. Missing → `[]`.
2. Selects verses: whole chapter, range-inclusive, or single verse.
3. Groups verses into slides: accumulate until **3 verses OR >200 chars OR
   last verse** (line 207). So long chapters auto-split; short ones group.
4. Each slide:
   ```json
   { "reference": "Psalms 23:1-3", "text": "1 The LORD is my shepherd; ...",
     "fullRef": "Psalms 23" }
   ```
   - Multi-verse slide text uses `"1 ... 2 ... 3 ..."` (numbers inlined).
   - **Single-verse slide text OMITS the leading verse number** (the
     reference header already says e.g. `John 3:16`).
   - `fullRef` is always the whole-chapter/range you asked for.
5. Verified examples: `Psalm 23` → 3 slides
   (`23:1-3`, `23:4-5`, `23:6`); `Genesis 1:1-5` → 2 slides (`1:1-3`,`1:4-5`);
   `John 3:16` → 1 slide; `Romans 8:28-30` → 2 slides.

## 5. HTTP endpoints — `presentation/views.py`

- `GET /api/scripture/parse?ref=<reference>`
  - 200 → `{"reference": "...", "slides": [...]}`
  - 400 → `{"error": "could not parse reference"}` (bad/partial ref)
  - 404 → `{"error": "passage not found in local Bible"}` (parses but the
    book/chapter/verses don't exist, e.g. `John 3:99` or missing kjv.json)
- `GET /api/scripture/books` → `{"books": [<66 canonical names>]}`
- Used by the phone's scripture tab for live typeahead validation, the
  `Preview` button, and queue "add scripture".

## 6. WebSocket path — presenting scripture to the display

Phone (`control.js`) sends:
```json
{"type": "command", "command": {"action": "present_scripture", "reference": "John 3:16"}}
```
Server (`consumer.py:handle_command` → `_present_scripture`, line 191):
1. `parse_reference(reference)`; if `None` → drops the command, **nothing
   happens on the display** (no error is returned to the control over WS —
   the control page does its own pre-validation via `/api/scripture/parse`).
2. `build_slides(ref)`; if empty → same silent drop.
3. Writes into the persistent room state:
   ```json
   { "contentType": "scripture",
     "itemId": null,
     "content": {"reference": "John 3:16", "slides": [...]},
     "slideIndex": 0, "slideCount": 1, "countdown": null, "blank": false }
   ```
4. Broadcasts a **full** `{"type": "state", "state": {...}}` to everyone in
   the room group (content changed → full snapshot once; later next/prev send
   only tiny `slide_change` messages with no content).

Display (`display.js`) on receiving that state calls
`renderScripture(content, slideIndex)`, which renders for the current slide:
```html
<div class="d-scripture">
  <div class="d-scripture__ref">JOHN 3:16</div>          <!-- uppercased by CSS -->
  <div class="d-scripture__text">“For God so loved the world, ...”</div>
</div>
```
The quotation marks are **curly “ ” added in JS** (display.js line ~112 and
control preview `renderPreviewInto`), not stored in kjv.json.

Display styling: `.d-scripture__ref` is white, bold, uppercase,
`clamp(2.5vw,4.5vw,4.2vw)`; `.d-scripture__text` is off-white and
`clamp(2vw,3.4vw,3.2vw)`. Both are multiplied by `var(--d-mult)`, which the
phone's **Style** tab adjusts (font/serif/sans, size small/medium/large,
background color or image) via the `set_style` WS command → `style_change`
message. So scripture size/font follow the global Style settings.

## 7. Phone UI (control.js)

- Scripture **tab** (`renderScripture`): an input box; on every keystroke it
  calls `/api/scripture/parse?ref=…` and shows "X slide(s)" or the 400 error
  inline. `Enter` or "Present Scripture" sends the WS command.
- A formatted reference includes a **Preview** button →
  `previewScripture(ref)` fetches the parse, then `openPreview` renders a
  16:9 mini-canvas using the same style settings — this is the
  "preview before sending" feature (the operator sees the exact slide first).
- "+ Add to Queue" posts `{item_type: "scripture", data: {reference: ...}}`
  to `/api/rooms/<code>/queue`.

## 9. Likely "what happened" failure checklist

1. **`presentation/data/kjv.json` missing/corrupt** → `_load_bible` returns
   `{}` → every parse returns 404 (parses OK but no slides). The JSON is
   NOT git-tracked anywhere else; deleting it breaks all scripture.
2. **Typeahead 400 spam** in server logs is expected (`ref=j`, `ref=john`).
   Only a COMPLETE ref must 200. Don't "fix" by forcing partial matches.
3. **WS `present_scripture` with an invalid ref** fails silently by design —
   the display won't change and the control gets no error over WS; the UI
   relies on the HTTP `/api/scripture/parse` pre-check.
4. **Out-of-range verse** (`John 3:99`) → parses to 0 slides → 404.
5. **Commas or complex ranges** (`Genesis 1,1`, `John 3:16-20-25`) are not
   supported → 400.
6. If the display looks wrong, check the **Style** settings (font/size/
   background) — scripture inherits them; the background image can wash out
   white text (there is a text-shadow fallback in CSS `.d-stage.has-bg`).
7. `kjv.json` loads lazily on first parse; the first request after boot is
   slightly slower (<100ms for 4.8MB).
